# 6-2. 次のコンテナの姿を考えよう

ここまでやってきたことを踏まえて、コンテナは**この先どうなっていく**のか、私たちは**どのように向き合っていく**べきなのかを考えてみましょう。

## コンテナの未来

コンテナの未来がどうなっていくのかは想像しかできませんが、**カギを握りそうな**技術をいくつかご紹介します。

### WASM (+ WASI)

ご存じの通り、**WASM (WebAssembly)** はブラウザ上で動作するバイナリフォーマットですが、**WASI (WebAssembly System Interface)** によって、ブラウザ外 (通常のOS環境) で動作させられるように仕様策定が進められています。  
このWASM + WASIの組み合わせが**コンテナと似たユースケースで利用**でき、なおかつ**高いセキュリティなどの利が得られる**のではないか、と期待されています。

例えば[runwasi](https://github.com/containerd/runwasi)を使うと、WASM + WASIのアプリケーションを**コンテナのように実行**することができます。  
runwasiが、**runcの担当部分を代替する**形で、WASMを実行できるようになっています。

WASMがコンテナに**成り代わる**のか、それとも結局コンテナが**使われ続ける**のか、あるいはそれぞれの得意分野に応じて**使い分けられる**のか、今後の動向に注目です。

### AIワークロードへの最適化

これまでコンテナの主な利用者は**Web産業**でしたが、近年のAIの発展に伴い、Web産業全体で多くの**AIワークロード**が動かされるようになってきています。  
これに伴い、今まで多数のWebワークロードを支えてきたコンテナに、**GPU対応**をはじめとした**AIワークロード向けの最適化**が求められるようになってきています。

AIワークロード向けの最適化は、ただGPUを使えるようにする**だけではありません**。  
様々なGPUが統一規格で使えるよう[CDI (Container Device Interface)](https://github.com/cncf-tags/container-device-interface) と呼ばれる**規格を策定**したり、分散学習のための**ネットワーク最適化** (例: [Linux Network Devices](https://github.com/opencontainers/runtime-spec/pull/1271)) を行ったりしています。

### コンテナをカーネルオブジェクトに？

実装して理解していただいた通り、コンテナは**複数の機能**をパッチワークのように**組み合わせて**実現されている技術です。  
カーネル内の**複数の概念**をユーザー空間で**無理やり組み合わせて**いるようなものなので、カーネル側では「コンテナ」自体が**認識できなかったり**、コンテナの削除時にエラーが起これば**コンテナの要素が一部残って**しまうこともあります。

これらの問題を解決するため、「Cell」という名前で**カーネル内にコンテナの概念を入れよう**、という[RFCが2026年10月に提出されました](https://lore.kernel.org/all/20261019-cells-rfc-6f4c85415f29@toxicpanda.com/)。  
採用されるかどうかは分かりませんが、もし採用されれば、コンテナの**信頼性や管理性が大きく向上**する可能性があります。

## みんなでコンテナの未来を作ろう

コンテナランタイムは、ほとんどのプロダクトが**OSSとして公開**されており、メンテナンスは**世界中のエンジニアの協力体制**によって成り立っています。  
つまり、コンテナの未来を作るのは私たち**一人ひとりのエンジニア**であり、**コミュニティ全体**なのです。  
ここまでのワークショップでコンテナの中身を (一部だけでも) 理解できた皆さんは、今すぐにでも**コンテナの未来を作る一員**となることができます。

もちろんruncへの貢献も素敵ですが、個人的にオススメなのは、[youki](https://github.com/youki-dev/youki)や[crun](https://github.com/containers/crun)のような新しい **(デファクトスタンダードでない) ランタイムへの貢献**です。  
利用者が少ないOSSには、**実際の環境で十分に使われていない**ため、まだ**見つかっていない問題**が多く存在します。  
だからこそ、自分の環境で**実際に使って検証**し、困りごとを見つけて**報告・修正**することは、そのOSS、ひいてはエコシステムへの**大きな貢献になります**。

このワークショップが、皆さんの**コンテナランタイムへの貢献の第一歩**となることを切に願っています。  
次はOSSの場、**コンテナの未来を話し合う場**でお会いしましょう。
