# 6-1. runcのコードを読んでみよう

これまでの章で何回か名前を挙げたruncは、**Goで実装された**低レベルコンテナランタイムで、現在**デファクトスタンダード**となっています。  
この節では、そんなruncのコードを実際に読むための糸口をつかむべく、**どこから読んでいけばいいのかのヒント**をお伝えします。

**runc**: <https://github.com/opencontainers/runc>

:::warning 注意
この章は、`runc v1.5.2`時点の情報に基づいています。
:::

## runcと`libcontainer`について

runcの機能の中核を担うのが、**libcontainer**というパッケージです。  
実はruncのCLI本体 (runcリポジトリ直下のファイル群) は、**libcontainerの薄いラッパー**でしかありません。

おススメの読み方は以下の通りです。

1. まず**特定のサブコマンド**に着目する
   - `runc create`および`runc init`が、今回実装した範囲に最も近い
2. リポジトリ直下の`{サブコマンド}.go`から、関数の定義をたどって処理の流れを追う

もちろん、runcはProduction Readyなランタイムであるため、コードは**非常に複雑**で**多くのケースを考慮**しています。  
インターネットで調べたりAIに聞いたりしながら**処理の大枠を把握**し、それを手掛かりに具体的な処理を追っていくのが良いでしょう。

## namespace分離・プロセス複製

数々の関数を経由して、最終的にnamespace分離やプロセス複製を行うのは`libcontainer/nsenter`パッケージです。

`nsenter`パッケージは非常に特殊なパッケージで、パッケージの**init関数からcgoを介してC言語のコードが実行**されます (`libcontainer/nsenter/nsenter.go` → `libcontainer/nsenter/nsexec.c`)。  
すなわち、runcのnamespace分離やプロセス複製の処理は、**Cで行われる**ということです。

この仕組みは、いくつかの理由が繋がった結果生まれています。

- 現在の低レベルコンテナランタイムの**要件が複雑**
  - **Rootless Container**をサポートするため、**Double Fork**を必要としている
    - `libcontainer/nsenter/nsexec.c#L800-L845`のコメントに詳しく書いてある
    - また、インターネット上で検索してみると、いくつか情報が出てくるはず
  - Double Forkだけでなく、**プロセス間通信**も考慮する必要がある
- **goroutine**という仕組みは、これらのように「**プロセス本体**を気にする」処理には**向いていない**
  - そもそもgoroutineが、プロセスを直接触るような難しい操作について**開発者が考えなくてもいい**ように設計されている
  - 考えなくてもいい = **深くは触れない** というトレードオフ
  - よって、Goで上記の処理を実装しようとすると、**複雑 / 冗長で分かりにくいコード**が生まれてしまう
- 最良の方法ではないが、この**特定の処理だけcgoに委任**し、コードが複雑になりすぎるのを防いでいる

`nsenter`パッケージは、runcの中でも**特にハッキー**な部分です。  
これを読むのが楽しいと思えたら、あなたも**コンテナ沼の住人**になれること間違いなし！

## マウント・rootfs処理

rootfsの分離に関しては、`libcontainer/rootfs_linux.go`というファイルに実装があります。  
今回実装した範囲は、`prepareRootfs()`関数に当たる部分です。

`prepareRootfs()`とその周辺は比較的**シンプルで読みやすい**ですが、こちらも**面白ポイントが色々**です。

- マウントは、**ファイルの種類**によって多数の処理に**分岐**する
- マウント設定のパース (別箇所) がかなり闇実装
- 設定によって`pivot_root()`と`chroot()`が**出し分けられている**
- `unix.PivotRoot(".", ".")`という**魔術**が行われている

読み進めていくと、複数の関数にまたがってはいますが、今回**実装した順番通り**にsyscallが呼ばれているのが確認できるはずです。  
まずはここから。ぜひトライしてみてください！

## cgroup

runcのcgroup関連処理は、実は**別リポジトリ**にあります。

**cgroups**: <https://github.com/opencontainers/cgroups>

cgroupsパッケージでは、cgroupの**v1 / v2両方に対応**した処理が実装されているだけでなく、DBusなど**ファイル書き込み以外の操作方法**にも対応しています。  
今回実装したのに近いのは`fs2`パッケージですね。

リポジトリ直下の`cgroups.go`には、`type Manager interface`が定義されています。  
子パッケージである`fs2`などがその**インターフェースを実装**しているため、`libcontainer`側では柔軟に実装を切り替えることができるのです。

コントロールする項目が多いため**分量は少々多い**ですが、やっていることは**シンプル**なので、順を追って読めば理解できるはずです。
